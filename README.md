# Husainiya PCDC — ERP / Loan Management

A Next.js (App Router) application implementing the PCDC Loan Management
module: loan applications, approval, loan agreement generation, signed
agreement upload/verification, disbursement, auto-generated repayment
schedules, overdue detection, payment reminder notices, an internal
notification feed, a monitoring dashboard, and a full audit trail.

UI is Tamil-first with English secondary labels throughout, per the PCDC
UI language requirement.

## Stack

- **Next.js 16** (App Router, Turbopack) + React 19 + TypeScript
- **Prisma 6** ORM, **SQLite** datasource (zero external dependency for
  local/dev — swap the `datasource` provider + `DATABASE_URL` in
  `prisma/schema.prisma` for Postgres/MySQL in production; no application
  code depends on the provider)
- Custom session-cookie authentication + role-based access control
  (no third-party auth service)
- **@react-pdf/renderer** for the Loan Agreement and Payment Reminder
  Notice PDFs
- **Zod** for input validation, **Vitest** for unit tests
- Local filesystem storage (`storage/`, gitignored) for generated PDFs and
  uploaded signed agreements, served only through an authenticated route

## Getting started

```bash
npm install
cp .env.example .env          # adjust SESSION_SECRET for anything beyond local dev
npx prisma migrate dev         # creates prisma/dev.db and applies migrations
npm run db:seed                # seeds org settings, one user per role, and demo loans
npm run dev
```

Open http://localhost:3000 — you'll be redirected to `/login`.

## Loan lifecycle implemented

```
PENDING → APPROVED → (Agreement Generated) → (Signed Agreement Uploaded)
        → (Signed Agreement Verified) → Disbursed → ACTIVE → COMPLETED
                                                            ↘ DEFAULTED (Admin/Board only)
```

A loan reference number (`PCDC-LN-<year>-<seq>`) is minted once, on
approval, and is never changed afterwards. Repayment schedules are
generated automatically the moment a loan is disbursed and becomes
`ACTIVE`. Overdue status, days/months overdue, and "reminder required"
are recomputed on read (no external cron in this environment) against
each instalment's due date.

See `AGENTS.md` for Next.js 16 conventions used by this codebase (async
`params`, Turbopack, etc.) — that file is regenerated by `next dev`/`next
build` and should stay checked in.
